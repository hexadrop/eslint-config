# Development and testing

## Working on `packages/eslint-config-yaml`

When rules, plugins, or config names change:

1. Update `packages/eslint-config-yaml/src/yaml.config.ts`.
2. Regenerate types with `bun run --filter @hexadrop/eslint-config-yaml build:types`.
3. Rebuild the package with `bun run --filter @hexadrop/eslint-config-yaml build` — the meta-package composes its `dist/`, so a stale build breaks root tests.
4. Run `bun run lint:fix` and `bun run typecheck` from the root.

## Tests

The suite is split by scope:

- `test/` — **unit tests**: the `yamlConfig()` factory contract (config names, plugin registration, language, globs, rule states), asserted against the composed config objects without executing a linter.
- `e2e/` — **end-to-end tests**: a real ESLint instance resolving the composed configs against fixture files with `fix` enabled, pinning diagnostics and the resulting content.

## Typegen

`scripts/typegen.ts` writes `src/typegen.d.ts` (git-ignored, regenerated by the `prepare` script on install). Never commit the generated file.
