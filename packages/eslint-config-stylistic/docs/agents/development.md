# Development and testing

## Working on `packages/eslint-config-stylistic`

When rules, plugins, config names or sections change:

1. Update `packages/eslint-config-stylistic/src/stylistic.config.ts`.
2. Regenerate types with `bun run --filter @hexadrop/eslint-config-stylistic build:types`.
3. Rebuild the package with `bun run --filter @hexadrop/eslint-config-stylistic build` — the meta-package composes its `dist/`, so a stale build breaks root tests.
4. Run `bun run lint:fix` and `bun run typecheck` from the root.

## Tests

`test/stylistic.test.ts` covers the factory contract through the highest available seam:

- **Sections**: config names, plugin registration and the on/off state of every optional section.
- **Peer matrix**: the typescript, json, astro, unicorn, perfectionist and format sections with each option on and off.
- **Peer auto-detection**: `local-pkg` is mocked with `mock.module()` to simulate every peer being installed or missing, including the actionable error when a peer is forced on but absent.
- **Composition**: consumer configs appended after the internal slice and the `stylistic: false` opt-out.
- **Snapshot**: the full config structure (plugins reduced to their keys).

## Typegen

`scripts/typegen.ts` resolves the pipeline with `astro`, `json`, `markdown` and `typescript` explicitly enabled, so the generated `ConfigNames` union includes every optional section. It writes `src/typegen.d.ts` (git-ignored, regenerated by the `prepare` script on install). Never commit the generated file.
