# Development and testing

## Working on `packages/eslint-config-core`

When rules, plugins or config names change:

1. Update the corresponding source (`src/core.config.ts`, `src/ignore.config.ts`, `src/imports.config.ts` or `src/config-names/`). The file globs live in `packages/eslint-config-shared/src/globs/`.
2. Regenerate types with `bun run --filter @hexadrop/eslint-config-core build:types`.
3. Rebuild the package with `bun run --filter @hexadrop/eslint-config-core build` — the meta-package composes its `dist/`, so a stale build breaks root tests.
4. Run `bun run lint:fix` and `bun run typecheck` from the root.

## Tests

`test/core.test.ts` covers the factory contract through the highest available seam:

- **Base rules**: setup, globals and rule states.
- **Node**: plugin registration and `eslint-plugin-n` rules.
- **Markdown**: source overrides.
- **Ignores**: default, additional and disabled configurations.
- **Imports**: setup, warnings, static analysis and the optional typescript/astro/stylistic slices.
- **Module flags**: CommonJS and webpack toggles.
- **Composition**: inline flat config items and appended consumer configs.

## Typegen

`scripts/typegen.ts` resolves the pipeline with every optional section enabled and writes `src/typegen.d.ts` (git-ignored, regenerated by the `prepare` script on install). Never commit the generated file.
