# Development and testing

Use the smallest command that validates the changed behavior.

## Commands

| Task                       | Command                                                        |
|----------------------------|----------------------------------------------------------------|
| Install dependencies       | `bun install`                                                  |
| Run all unit tests         | `bun run test`                                                 |
| Run tests for this package | `bun test packages/eslint-config-markdown`                     |
| Run the unit tests         | `bun test packages/eslint-config-markdown/test`                |
| Run the e2e tests          | `bun test packages/eslint-config-markdown/e2e`                 |
| Run tests for one file     | `bun test packages/eslint-config-markdown/test/<file>.test.ts` |
| Lint and fix               | `bun run lint:fix`                                             |
| Type-check                 | `bun run typecheck`                                            |
| Build this package         | `bun run --filter @hexadrop/eslint-config-markdown build`      |

## Working on `packages/eslint-config-markdown`

When plugins, processors, the parser, or config names change:

1. Update `packages/eslint-config-markdown/src/markdown.config.ts` (or `markdown.globs.ts` for the targeted files).
2. Regenerate types with `bun run --filter @hexadrop/eslint-config-markdown build:types`.
3. Rebuild the package with `bun run --filter @hexadrop/eslint-config-markdown build` — the meta-package composes its `dist/`, so a stale build breaks root tests.
4. Run `bun run lint:fix` and `bun run typecheck` from the root.

## Tests

The suite is split by scope:

- `test/` — **unit tests**: the `markdownFactory()` contract (config names, plugin registration, globs, merged processor and parser-plain wiring), asserted against the composed config objects without executing a linter.
- `e2e/` — **end-to-end tests**: a real ESLint instance resolving the composed configs against markdown fixture files, pinning what a user actually sees (diagnostics on the markdown file itself, content after `--fix`).

## Typegen

`scripts/typegen.ts` writes `src/typegen.d.ts` (git-ignored, regenerated by the `prepare` script on install). Never commit the generated file.
