# Development and testing

Use the smallest command that validates the changed behavior.

## Commands

| Task                       | Command                                                     |
|----------------------------|-------------------------------------------------------------|
| Install dependencies       | `bun install`                                               |
| Run all unit tests         | `bun run test`                                              |
| Run tests for this package | `bun test packages/eslint-config-astro`                     |
| Run the unit tests         | `bun test packages/eslint-config-astro/test`                |
| Run the e2e tests          | `bun test packages/eslint-config-astro/e2e`                 |
| Run tests for one file     | `bun test packages/eslint-config-astro/test/<file>.test.ts` |
| Lint and fix               | `bun run lint:fix`                                          |
| Type-check                 | `bun run typecheck`                                         |
| Build this package         | `bun run --filter @hexadrop/eslint-config-astro build`      |

## Working on `packages/eslint-config-astro`

When plugins, rules, or config names change:

1. Update `packages/eslint-config-astro/src/astro.config.ts` (or `astro.globs.ts` for the targeted files).
2. Regenerate types with `bun run --filter @hexadrop/eslint-config-astro build:types`.
3. Rebuild the package with `bun run --filter @hexadrop/eslint-config-astro build` — the meta-package composes its `dist/`, so a stale build breaks root tests.
4. Run `bun run lint:fix` and `bun run typecheck` from the root.

## Tests

The suite is split by scope:

- `test/` — **unit tests**: the `astroFactory()` contract (config names, plugin registration, globs, typescript-parser matrix, optional-peer error), asserted against the composed config objects without executing a linter.
- `e2e/` — **end-to-end tests**: a real ESLint instance resolving the composed configs against astro fixture files, pinning what a user actually sees (diagnostics, content after `--fix`).

`@hexadrop/eslint-config-typescript` is not installed in this repository, so the optional peer is always absent here: the typescript-flavor unit tests use `peerCheck: false` and the e2e matrix only covers the js-only parsing path. The typescript flavor is exercised end to end through the `@hexadrop/eslint-config` meta-package suite.

## Typegen

`scripts/typegen.ts` writes `src/typegen.d.ts` (git-ignored, regenerated by the `prepare` script on install). Never commit the generated file.
